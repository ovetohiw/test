# NETWORK.md

Этот файл задаёт конвенции сетевого взаимодействия для людей и AI-агентов.
Правила стек-агностичны: они действуют до выбора стэка и после него.
Конкретные протоколы, фреймворки и хостинг смотрите в STACK.md, когда они отмечены.
Секреты, TLS и доверие клиенту — также docs/convesion/SECURITY.md.
Логи сетевых вызовов — docs/convesion/LOGGING.md.

Нарушение — доверие ненадёжной сети, бесконечный ретрай, обход TLS,
секреты в URL или теле без нужды, или внешний вызов без таймаута и явного отказа.

## Границы и контракты

- Сеть — граница системы. Вход и выход валидируйте явно: схема, размер, тип, обязательные поля.
- Контракт API важнее удобства реализации. Меняйте публичный контракт осознанно, с записью в FEATURE.md или плане.
- Не смешивайте внутренний и внешний API без решения. Внутренний вызов не обязан повторять публичный формат.
- Идентификаторы, версии и имена полей стабильны. Не переименовывайте публичные поля «заодно» с фичей.
- Пока стиль API не выбран в STACK.md, не вводите второй стиль «временно» в той же границе.

## Транспорт и TLS

- Соблюдайте docs/convesion/SECURITY.md.
- Не отключайте проверку TLS и сертификатов, чтобы «заработало локально». Локальный обход не коммитьте и не включайте по умолчанию.
- Секреты не кладите в query-параметры, фрагменты URL и логируемые заголовки.
- Cookie и токены передавайте только по защищённому каналу в средах, где это ожидается.
- Не открывайте порт наружу шире, чем нужно задаче. Слушать `0.0.0.0` без причины — риск, который фиксируйте явно.

## Таймауты и отмена

- У каждого исходящего сетевого вызова есть таймаут. Бесконечное ожидание запрещено.
- Таймаут выбирайте по роли вызова: пользовательский запрос короче фоновой синхронизации.
- При отмене клиента или дедлайне не оставляйте фоновый вызов без привязки к контексту отмены, если стэк это поддерживает.
- Таймаут — отказ, а не успех с пустым телом. Вызывающий получает явный сигнал ошибки.
- Вложенные вызовы не суммируйте молча: суммарное время должно укладываться в бюджет внешнего запроса.

## Повторы и идемпотентность

- Повторяйте только безопасные или явно идемпотентные операции. Слепой ретрай `POST`, который создаёт ресурс, запрещён без ключа идемпотентности.
- Число попыток ограничено. Бесконечный цикл ретраев — нарушение.
- Между попытками используйте паузу с ограничением (backoff). Не долбите зависимость на полной скорости.
- После исчерпания попыток возвращайте явный отказ. Не маскируйте его успешным пустым ответом.
- Ретраи логируйте с номером попытки и исходом по docs/convesion/LOGGING.md, без спама одной строки на каждый тик.

## Ошибки и статус

- Сетевой сбой, таймаут, 4xx и 5xx различайте. Не сводите всё к «ошибка сети».
- Клиенту отдавайте безопасное сообщение. Стек, внутренний URL и тело зависимости наружу не являются ответом. Подробности — в docs/convesion/SECURITY.md.
- Ожидаемый отказ валидации и отказ в доступе обрабатывайте явно. Молчаливый fallback к «разрешено» или к устаревшим данным без пометки запрещён.
- Частичный успех при нескольких вызовах фиксируйте: что применено, что нет. Не притворяйтесь полной готовностью.
- Поведение при сетевой ошибке проверяйте тестом по docs/convesion/TEST.md так же, как счастливый путь.

## Внешние зависимости

- Исходящий вызов именуйте: какая зависимость, зачем, какой исход. Не размазывайте URL по бизнес-коду без обёртки границы.
- Базовый URL, ключи и таймауты — из конфигурации окружения, не хардкод в логике фичи.
- Не ходите в прод и в живой интернет из тестов. Сеть в тесте задаётся явно: мок, тестовый стенд или запрет. Правила — в docs/convesion/TEST.md.
- Новая внешняя зависимость допустима только если нужна текущей фиче и отражена в STACK.md.
- При деградации зависимости решайте явно: отказ, кэш с пометкой устаревания или очередь. Тихий «как будто ок» запрещён.

## Входящие запросы

- Не доверяйте заголовкам, IP и полям клиента для прав, цены и владельца. Проверка — на сервере. См. docs/convesion/SECURITY.md.
- Ограничивайте размер тела и число заголовков на границе. Неограниченный upload — риск.
- CORS, CSRF и origin настраивайте осознанно. «Разрешить всем» без решения в плане запрещено.
- Health-check и readiness отделяйте от бизнес-логики: они не должны требовать секретов клиента и не должны быть тяжёлыми.
- Публичный эндпоинт без аутентификации допустим только если это явно задумано и проверено.

## Версии и совместимость

- Ломающее изменение публичного контракта сопровождайте версией или согласованной миграцией клиентов.
- Не ломайте существующих клиентов ради удобства текущей сессии без записи риска в PROGRESS.md.
- Поля «на будущее» не добавляйте пачками без нужды текущей фичи.
- Устаревший эндпоинт помечайте и выводите по плану, а не удаляйте молча в той же правке, что чинит баг.

## Объём и нагрузка

- Не тяните лишние данные по сети «на всякий случай». Запрашивайте и отдавайте то, что нужно сценарию.
- Пагинация и лимиты обязательны там, где список может расти без верхней границы.
- Клиент не должен без нужды открывать лишние постоянные соединения. Долгий канал (WebSocket, SSE) — только если выбран в STACK.md и нужен фиче.
- Нагрузку и лимиты частоты не обходите локальным костылём в проде. Если лимит мешает — это открытое решение, не тихий disable.

## Конфиг и среды

- Хосты, порты, базовые URL и таймауты различаются по средам. Не зашивайте prod-хост в код «потому что локально так же».
- В репозитории — примеры с плейсхолдерами. Рабочие адреса с секретами в query — запрещены.
- Локальный прокси, mock-сервер и туннель не становятся частью прод-пути, пока не записаны в стэк или план.
- Изменение сетевой топологии (новый сервис, новый порт наружу, смена протокола) — отдельное решение, не побочный эффект фичи.
- Новый внутренний сервис и сеть между своими частями — только если в STACK.md отмечен Микросервис, либо есть явный план смены архитектуры. При отмеченном Монолите модули общаются внутри приложения, не через новую сеть «как у сервисов». См. docs/convesion/ARCHITECTURE.md.

## Проверка и готовность

- Фича с сетевым вызовом не готова, если нет явного таймаута, обработки отказа и проверки поведения.
- Сквозной критический путь с сетью проверяйте по docs/convesion/TEST.md. Мок, который повторяет свою же логику, не заменяет нужную интеграцию.
- Health-check из AGENTS.md должен отражать готовность принимать трафик, а не «процесс просто жив», если зависимости критичны.
- Если проверить сеть в этой сессии нельзя — запишите блокер в PROGRESS.md. Не объявляйте устойчивость «на глаз».

## Правила для AI-агента

- Не отключайте TLS, CORS и проверки origin, чтобы быстрее пройти сценарий.
- Не оставляйте исходящий вызов без таймаута и без явной обработки ошибки.
- Не ретрайте неидемпотентные операции без ключа и лимита попыток.
- Не ходите в живой интернет и прод из тестов.
- Не кладите секреты в URL, query и логи сетевых вызовов.
- Не вводите новый протокол, брокер или API-стиль, которых нет в STACK.md.
- При сомнении остановитесь и запишите риск в PROGRESS.md или в открытый exec plan.
- Соблюдайте docs/convesion/SECURITY.md, docs/convesion/TEST.md, docs/convesion/DEVELOPMENT.md и docs/convesion/LOGGING.md. Этот файл их не заменяет.
